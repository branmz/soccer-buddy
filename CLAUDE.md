# Soccer Buddy

Local-first, offline Android app for soccer coaches: multi-team rosters, drag-and-drop
formations, and live match-day management (clock, subs, quick-sub presets, event logging).
No backend, no auth — all data lives in on-device SQLite.

## Stack

- Expo SDK 57 + React Native 0.86 + TypeScript (strict), runs in Expo Go. See `AGENTS.md`:
  always check the versioned Expo docs (v57) before touching Expo APIs
- expo-router (tabs = @react-navigation/bottom-tabs under the hood)
- expo-sqlite + drizzle-orm (drizzle-kit for migrations)
- Zustand (UI/editor state only — SQLite is the source of truth)
- react-native-gesture-handler + react-native-reanimated (drag & drop), react-native-svg (pitch)
- NativeWind v5 RC + Tailwind v4 (classes via `className`; theme tokens in `src/global.css`)
- Jest (jest-expo) for domain logic; ESLint (eslint-config-expo) + Prettier

## Commands

- `npx expo start --android` — run in Expo Go / emulator
- `npm run check` — lint + format check + typecheck + test (must pass before every commit)
- `npm run lint` / `npm run lint:fix` — ESLint, zero warnings allowed
- `npm run format` / `npm run format:check` — Prettier
- `npm run typecheck` — `tsc --noEmit`
- `npm test` — Jest
- `npx drizzle-kit generate` — generate a migration after editing `src/db/schema.ts`
- Always add native deps with `npx expo install <pkg>` (never plain `npm install`)
- Dev deps: `npx expo install <pkg> -- --dev` in Bash. PowerShell drops the `--dev`, so check
  that new tooling landed in `devDependencies`
- NativeWind/react-native-css/tailwindcss/lightningcss are pinned to exact versions (v5 RC);
  upgrade them together, never individually

## Environment Gotchas

- Windows dev machine. If `node` isn't on PATH, prepend `C:\Program Files\nodejs`
- npm 11 blocks install scripts until approved (`npm approve-scripts`). If drizzle-kit
  (esbuild) or Tailwind (oxide) fail with a missing-binary error, approve the script first
- `expo-env.d.ts` is generated by `expo start` and gitignored; `nativewind-env.d.ts`
  references `expo/types` so `tsc` works on a fresh clone

## Project Layout

- `src/app/` — expo-router routes only. `(tabs)/` = teams · tactics · game · history, each a
  folder with its own Stack `_layout.tsx`
- `src/db/schema.ts` — Drizzle schema; `src/db/migrations/` is generated, never hand-edit
- `src/db/repositories/` — all DB writes go through these typed async functions
- `src/domain/` — pure TS logic (clock, lineup replay, sub rules, playing time, stats,
  formation JSON parsing). No React, no DB imports. Unit tested in `src/domain/__tests__/`
- `src/constants/presetFormations.ts` — built-in formations per field size (5/7/9/11)
- `src/stores/` — Zustand: `appStore` (activeTeamId, persisted via expo-sqlite/kv-store),
  `boardStore` (formation editor), `liveMatchStore` (live-screen UI state)
- `src/components/pitch/` — shared Pitch, PlayerToken, BenchSidebar, DragLayer
- `src/components/game/` — ClockBar, EventActionBar, EventTimeline, QuickSubBar
- `src/components/ui/` — generic primitives

## Architecture Rules

- **SQLite is the source of truth.** Read with Drizzle `useLiveQuery`; write via repositories.
  Multi-row writes use `db.transaction`. Don't mirror DB data in Zustand.
- **Match clock is timestamp-derived.** Never count ticks. Elapsed =
  (paused_at ?? ended_at ?? now) − started_at − paused_total_ms, per `match_periods` row.
  Every start/pause/resume/end is persisted immediately. UI intervals only trigger re-renders.
- **Live lineup is event-sourced.** `deriveLineup(starting_lineup_json, events)` replays
  `substitution`, `position_swap`, `red_card`. Never store the current lineup separately.
  Undo = delete the latest event `group_id`.
- **Coordinates are normalized 0–1** (`y = 1` = own goal line). Convert to pixels only in
  `Pitch` using measured layout.
- `starting_lineup_json` is a snapshot — editing a formation never rewrites match history.
- Players referenced by events can't be hard-deleted; deactivate them (`is_active = false`).
- Keep `src/domain` pure and covered by tests; put new business rules there, not in screens.
- Gestures: use `Gesture.Pan()` + shared values; hop to JS with `runOnJS` only on drop.
  Every drag action must also have a tap-to-select fallback.

## Code Style

- TypeScript strict; no `any` (use `unknown` + parse helpers for JSON columns)
- Function components + hooks; named exports (except expo-router route files)
- Styling via NativeWind `className`; inline `style` only for animated/measured values
- Files: components `PascalCase.tsx`, everything else `camelCase.ts`
- Formatting is owned by Prettier — don't hand-format
- A PostToolUse hook (`.claude/hooks/lint-changed-file.mjs`) runs Prettier + ESLint on every
  edited file; fix any reported errors before moving on

## Testing

- Write domain tests first for clock, lineup, subRules, playingTime, stats
- Manual Android checks for gestures, clock across screen lock, and app-kill resume

## Git Conventions

### Branching

```
feature/live-match-clock               # New features
fix/bench-drag-scroll-conflict         # Bug fixes
docs/update-readme                     # Documentation only
chore/upgrade-expo-sdk                 # Maintenance, tooling
refactor/extract-pitch-token           # Code refactoring
style/roster-row-spacing               # Visual/style changes
```

- Branch off `main` for all new work
- Keep branches short-lived; open a PR when ready
- Delete branches after merging

### Commit Messages

Follow **Conventional Commits**:

```
feat: add quick-sub presets to live match
fix: keep clock accurate after screen lock
docs: update README with setup steps
chore: upgrade expo-sqlite to latest
refactor: extract lineup replay into domain module
style: fix spacing on bench sidebar
```

- Use present tense, lowercase, no period at the end
- Keep the subject line under 72 characters
- Add a body for non-obvious changes

### Pull Requests

- PR title should match the commit message format
- Include a summary and test plan in the PR description
- Target `main` as the base branch
